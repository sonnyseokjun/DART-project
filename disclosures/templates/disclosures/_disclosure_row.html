{% comment %} 공시 한 장 — 목록 화면 공용 컴포넌트. **윗판 + 아랫글의 카드다.** 윗판(`.filing-plate`)은 연회색 면이고 기업·날짜·표시가 위에 붙은 뒤 공시명이 `margin-top: auto` 로 판 아래로 밀린다. 아랫글은 면이 없이 열에 바로 붙는다 — 테두리도 그림자도 없다(DESIGN.md Shapes · Elevation). 요약이 아직 없는 공시는 윗판의 면을 비우고 점선으로 두른다. 내용이 오지 않은 자리를 알리는 이 언어의 장치다(DESIGN.md Elevation & Depth). 필요한 컨텍스트: `disclosure` (summary·company 가 select_related 되어 있어야 N+1 이 없다). `hide_company` 를 True 로 넘기면 기업명을 감춘다(기업 상세처럼 이미 아는 화면용). 카드에서 DART 원문 링크를 함께 노출하는 이유: 목록만 훑는 사용자도 원문 대조 경로를 가져야 한다(PLAN.md 5.3). 상세 화면에만 두면 요약을 그대로 믿고 넘어가기 쉽다. **요약을 기다리는 카드에서는 이 링크가 유일한 정보 경로**라 더 중요하다. `is_summary_pending` 은 요약이 아직 없는 상태다. 없는 이유(요청 전·정리 중·실패·대상 아님)는 `summary_state` 가 가르고, 안내 문구와 "AI 요약 보기" 버튼은 `_summary_status.html` 이 그린다. 노출 여부 자체는 views.published_disclosures() 가 정하므로 여기서 다시 따지지 않는다. 요청 버튼을 고스트로 넘기는 이유: 요약 대기 공시가 여섯 장이면 채움 파랑도 여섯 개가 되어 "1차 행동이 무엇인가"가 사라진다. 상세 화면에서는 그 공시 하나뿐이므로 거기서만 채움 파랑을 쓴다. {% endcomment %}
